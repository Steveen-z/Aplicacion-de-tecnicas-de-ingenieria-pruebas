# Evaluación ISO/IEC 25010

Evaluación del backend InmobiSV tras la fase 2 (noviembre de 2026). Cada fila indica solo lo que se **comprobó ejecutando** el sistema el 2026-11-25 (detalle en [pruebas.md](pruebas.md)) y lo que queda sin evidencia. El frontend todavía no existe, así que la evaluación se limita a la API.

| Característica | Evaluación | Evidencia comprobada | Pendiente / sin evidencia |
|---|---|---|---|
| Adecuación funcional | Alta | 61 comprobaciones funcionales (F01–F56) aprobadas contra la API real con PostgreSQL 16 + PostGIS, sobre una base creada desde cero. Cubre P01–P12 y lo que exige el documento de arquitectura: búsqueda por cercanía, casas/lotes/terrenos, perfil propio, gestión de usuarios, moderación y auditoría. Se encontraron y corrigieron 10 defectos o carencias reales (ver "Errores identificados", filas 5–17) | Puntos de interés de Overpass no verificados con red real (quedan `SIN_DATOS`); el aviso de baja de precio solo es interno, sin correo ni push |
| Eficiencia de desempeño | Aceptable para prototipo | Índice GiST para la búsqueda por radio, índices por estado, tipo y favoritos; paginación (máx. 50); tope de 2000 candidatas por radio; 20 peticiones seguidas al listado en 0,18 s con 16 publicaciones (fase 1) | Sin pruebas de carga ni con volumen realista; el orden por distancia se hace en memoria (válido para cientos de publicaciones) |
| Compatibilidad | Buena | API REST JSON; OpenAPI en `/api/docs`; CORS con credenciales y orígenes explícitos (preflight verificado en F53); Bearer para herramientas y cookie para navegador | No probado con el frontend real |
| Usabilidad | Limitada (solo API) | Mensajes en español con `code`, `details` y `requestId`; 400 para errores de forma y 422 para reglas de negocio, de forma consistente (P03 y P12 corregidos); `/health` explica qué falta (migración o PostGIS) | La interfaz final depende del frontend |
| Fiabilidad | Alta para el alcance | Precio, historial y avisos en una sola transacción (verificado forzando un fallo: no queda nada a medias); auditoría en la misma transacción que cada acción; UPDATE condicional contra cambios concurrentes (carrera real: 1×200, 3×409); migraciones transaccionales que no se reaplican; compensación al fallar el registro de una subida; limpieza de huérfanos repetible | Sin pruebas de recuperación ante caída de la BD ni copias de seguridad |
| Seguridad | Buena para prototipo | Verificado en ejecución: CSRF con cookie HttpOnly (sin token o con `Origin` ajeno → 403); Bearer revocable; roles y propiedad (403 en edición ajena, imagen ajena y documento ajeno); bloqueo con cierre inmediato de sesiones; auditoría que no se puede modificar ni borrar (trigger); fotos solo de la propia plataforma; coordenadas exactas ocultas al público; rate limiting (429); helmet; protección contra path traversal (prueba unitaria) | `npm audit --omit=dev`: 4 avisos de severidad alta en dependencias transitivas, sin revisar; DUI sin dígito verificador; `JWT_SECRET` de ejemplo aceptado si no se cambia; sin auditoría externa |
| Mantenibilidad | Alta | Capas domain/application/infrastructure/presentation con puertos; 82 pruebas unitarias con repositorios falsos (y una mutación deliberada detectada); esquema versionado con `scriptdb.sql` generado y una prueba que detecta si se desincroniza; diseño documentado en `docs/diseno-fase2.md` | Sin medición de cobertura; los repositorios Prisma se prueban con el script funcional, no con pruebas de integración automatizadas |
| Portabilidad | Buena | Configuración por variables de entorno (validadas al arrancar); migraciones aplicables con `psql` o pgAdmin en Windows; `docker-compose` con imagen `postgis/postgis:16-3.4`; almacenamiento detrás del puerto `FileStorage` | PostGIS es una dependencia nueva que cada integrante debe instalar; `docker compose` no se pudo probar (sin Docker en el entorno de verificación); archivos en disco local |
