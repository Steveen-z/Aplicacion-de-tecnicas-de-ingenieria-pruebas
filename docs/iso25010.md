# Evaluación ISO/IEC 25010

Evaluación del backend InmobiSV v1.0.0 con las correcciones de noviembre de 2026. Cada fila indica solo lo que se **comprobó ejecutando** el sistema el 2026-11-25 (detalle en [pruebas.md](pruebas.md)) y lo que queda sin evidencia.

| Característica | Evaluación | Evidencia comprobada | Pendiente / sin evidencia |
|---|---|---|---|
| Adecuación funcional | Alta | 22 casos funcionales F01–F22 (26 comprobaciones) aprobados contra la API real con PostgreSQL 16. Se encontraron y corrigieron 2 defectos: P03 (400 en vez de 422, cliente sin teléfono bloqueado) y P12 (400 en vez de 422) | P04 "invitación a registrarse" y P06 con puntos de interés reales no se verificaron con Overpass (sin red en el entorno) |
| Eficiencia de desempeño | Aceptable para prototipo | Listado paginado; índices del script SQL; 20 peticiones seguidas al listado en 0,18 s con 16 publicaciones | Sin pruebas de carga ni con volumen realista de datos |
| Compatibilidad | Buena | API REST JSON; OpenAPI en `/api/docs` (200); CORS configurable por `CORS_ORIGINS` | No probado con el frontend (aún no existe en este repositorio) |
| Usabilidad | Limitada (solo API) | Mensajes de error en español con `code` y `details` (p. ej. P03 devuelve la lista completa de requisitos pendientes); Swagger para explorar | La interfaz de usuario final depende del frontend |
| Fiabilidad | Media-alta | Arranque con falla rápida si faltan variables (`validateEnv`); `/api/health` comprueba la BD; filtro global de errores; si falla Overpass la valoración queda `SIN_DATOS` sin romper el detalle (observado: F16); si fallan las notificaciones el precio se mantiene (prueba unitaria) | Notificaciones de baja de precio no atómicas con el cambio; sin pruebas de recuperación ante caída de la BD |
| Seguridad | Buena para prototipo | Comprobado en ejecución: contraseñas débiles y campos extra → 400; JWT revocado tras logout → 401; JWT `alg: none` → 401; roles (cliente no publica → 403; edición ajena → 403); rate limiting de login → 429; cabeceras helmet (CSP, HSTS, nosniff); archivo PHP renombrado a .jpg rechazado por firma; coordenadas exactas ocultas al público; WhatsApp solo con sesión | Sin auditoría externa ni análisis de dependencias resuelto (`npm audit` reporta 7 avisos en dependencias); DUI sin dígito verificador; `.env.example` trae un `JWT_SECRET` de ejemplo que la validación acepta (debe cambiarse en cada despliegue) |
| Mantenibilidad | Alta | Capas domain/application/infrastructure/presentation; puertos con token Symbol; los casos de uso se probaron con repositorios falsos sin cambiar el código de producción; 38 pruebas unitarias (`npm test`), y una mutación deliberada es detectada | Sin medición de cobertura; sin pruebas de integración automatizadas de los repositorios Prisma (cubiertos solo por el script funcional) |
| Portabilidad | Buena | Configuración por variables de entorno; el mismo `db/scriptdb.sql` funcionó en PostgreSQL 16 local sin Docker; `package-lock.json` versionado; almacenamiento de archivos detrás del puerto `FileStorage` | `docker compose` no se pudo probar en el entorno de verificación (sin demonio Docker); archivos en disco local |
